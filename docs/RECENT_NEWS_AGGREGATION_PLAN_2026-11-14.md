# 商业航天近期资讯聚合改造计划

产品目标是方便查看国内外商业航天近期发展，国内按省份和公司浏览。采用最多 30 天的滚动资讯窗口，不建设长期新闻档案。延续现有 React、Vite、TypeScript 和 Cloudflare Pages，把采集移至 GitHub Actions，发布少量 JSON 快照；网页读取快照，不依赖 D1 新闻查询。

## 产品范围

| 项目 | 首版规则 |
| --- | --- |
| 默认浏览 | 最近 7 天，可切换 24 小时、7 天和 30 天 |
| 保留边界 | 最多 30 天且最多 2,000 条去重资讯，先达到哪项就按哪项裁剪 |
| 首屏 | 国内优先的近期动态，显示文章发布时间和实际采集更新时间 |
| 国内分类 | 全国、省份、公司；省份与公司可以组合筛选 |
| 内容类型 | 新闻、政策公告、项目动态、采购公告 |
| 国外分类 | 国家或地区、机构、公司、专业媒体 |
| 阅读方式 | 标题直接打开原文；卡片可显示来源提供的短摘要 |
| 来源目录 | 按省份、公司长期保留官网和栏目链接，与文章保留窗口分开 |
| 发射 | 保留未来 30 天、最多 100 条计划及来源更新时间，跳转原始信息 |
| 搜索 | 仅对当前快照中的标题、来源和公司做本地搜索 |

窗口以来源的真实发布时间计算，抓取时间不能把旧闻变成新消息。无可确认日期的入口保留在来源目录，不进入近期时间线。达到数量上限时按时间保留最新记录，显示实际最早日期及已达条目上限，不能声称覆盖完整 30 天。

历史文章全文、图片、政策附件、无限滚动历史库、历史全文检索和自动生成长期趋势报告均不属于首版。英文原题和原文链接保留，已有可靠译题可沿用；新增采集不依赖付费翻译、AI 摘要或本机服务。

## 页面与分类

沿用“概览、资讯、发射、官方”四个主入口。资讯增加国内/国外、省份、公司和时间筛选；官方页复用同一份资讯数据，只展示政策、申报、公示、采购等信息。公司页作为资讯索引，地区入口直接放在资讯筛选区，首版无需增加复杂省级详情站。来源目录从次级入口进入。

省级区域和公司都通过固定 ID 关联文章，同一条资讯只保存一次。省份来源于政策适用区域或明确项目发生地，企业总部单独记录；不能把企业所有新闻自动归入总部省份。国家政策进入“全国”，地方转载不变成地方新政策。不确定的归属保留“未明确”，不猜测。

配置维护公司正式名称及别名，避免把同名词自动当作公司命中。政策适用地区、项目地区、发布机构属地分别保存。首版筛选使用前两者，发布机构属地仅作出处参考。

保留现有公司路径与 `/policy` 到官方页的兼容入口。现有文章数字 ID 链接在过渡期仍走旧页面；新卡片直接跳转原文。最终停用 D1 文章读取后，历史数字链接显示“站点仅保留近期资讯”的恢复页和来源目录入口，不读取或伪造已不存在的记录。专题页可暂作固定关键词筛选，避免为低使用率功能维护另一套数据库查询。

## 技术结构

```text
Git 中的来源、地区、公司配置
            ↓
GitHub Actions 定时运行 TypeScript 采集脚本
            ↓
读取上次快照，按到期时间采集，去重、分类、裁剪
            ↓
校验后写入 R2 中的一份 current.json
            ↓
Cloudflare Pages 的只读函数提供缓存响应
            ↓
现有 React 页面在浏览器内筛选和搜索
```

R2 继续使用已配置的对象桶，数据放到独立的 `recent/v1/` 前缀，避免影响现有资源。首版只有一个公开快照对象、一个失败恢复用的前一版对象，以及一个很小的内部运行预算对象，不为每个省、每个公司复制文章文件。单次对象写入完成后才提供新版本，读者拿到完整旧文件或完整新文件。

`current.json` 同时包含资讯、公司与地区索引、发射计划和脱敏的每源状态，避免多文件切换时数据版本不一致。字段包括 `schemaVersion`、`builtAt`、`lastDataUpdatedAt`、`retentionDays`、`coverageStart` 和 `truncated`。每源状态包含最近尝试、最近成功、下次允许尝试时间、错误类别以及 ETag/Last-Modified。`builtAt` 不等于内容已更新，网页的新鲜度使用采集成功时间。

文章只保留稳定 ID、规范与原始 URL、标题、真实发布日期、发布方、来源 ID、公司 ID、地区 ID、类型及可选短摘要。摘要最多 160 个字符，去掉 HTML；源状态只保留当前值，不累积逐次运行日志。没有新数据也要执行窗口裁剪。生成及前一版快照均执行相同的滚动保留规则，旧内容不留在备份中形成隐性档案。

每次发布前检查条数、JSON 字节体积、引用关系、真实日期和 schema。初始上限为未压缩 3 MiB，移动端传输目标为压缩后 500 KiB 以内，以样本测量验收。优先裁掉摘要，仍超限则按时间缩小记录窗口并明确覆盖范围。规模超出这一边界时再讨论按国内/国外拆分，首版不引入分片索引和搜索服务。

快照由现有 Pages Functions 的 `R2_ASSETS` 绑定读取，新增的 `/api/recent` 只做对象读取、ETag 和缓存响应，不按筛选条件查询数据库。浏览器复用这一份数据完成筛选。现有 API hooks 要增加快照适配层，不能仅改某一个页面后仍让公司、官方或统计接口偷偷读 D1。

响应缓存初始设为 10 分钟，进入页面或手动刷新时更新，移除现有资讯页每 5 分钟后台轮询。缓存命中减少 R2 回源，但经过函数的请求仍占用函数请求额度。数据缺失返回可理解的暂无更新状态，不能自动回退到昂贵 D1 查询。

## 采集与更新

初始调度每天 4 次，目标北京时间 08:17、12:17、18:17、22:17，对应 UTC cron `17 0,4,10,14 * * *`。政策和采购来源每天 2 次，企业、专业媒体和发射数据最多 4 次，按每源到期时间执行。先接受小时级更新，不做实时倒计时或直播服务。

GitHub Actions 调度可能延迟、漏跑，公共仓库长期不活跃时定时工作流也可能被停用。因此提供 `workflow_dispatch` 手动补跑，页面保留更新时间；最近成功采集超过 24 小时显示延迟，超过 48 小时明确显示更新异常。月度来源维护时同时检查定时工作流是否启用。不能用频繁请求 health 代替任务状态。

尽量复用 `src/ingestion/collectors/` 中的 RSS、官方网页、采购、SNAPI 和 LL2 适配器，以及 `collectSource` 的规范化与去重入口。新执行脚本不调用 `persistedRun`、D1 catalog sync、实体全量回填或 D1 retention cleanup；用快照内的有限数据做分类和清理。沿用 TypeScript，避免为这次改造再引入 Python 服务或另一套前端框架。

单源最多取 2 个公开列表页，最多处理 30 条候选，25 秒超时，全局并发 3，单次任务 20 分钟上限。优先利用条件请求；有公开 RSS/API 时优先使用。首版不依赖登录、验证码、浏览器自动化或私有接口。429 遵守 Retry-After；网络错误等不立即循环重试，保留每源下次尝试时间并退避，其他来源照常运行。

单源失败保留仍处于窗口内的旧条目，并更新失败状态；整个采集任务失败时继续展示上次成功快照。校验不通过不发布残缺文件。浏览器还应按当前时间过滤超出 30 天的内容，避免调度长期中断时把旧闻继续当作近期资讯。所有源均失败时，不能仅凭文件重新生成就刷新“内容已更新”标记。

R2 是上一轮状态的持久来源，不依赖易失的 Actions cache 或本机磁盘。工作流配置单个 concurrency group，发布任务不并发覆盖快照；其他工作流不写该对象。写入使用仅授权目标桶的 GitHub Secret，页面只公开元数据和脱敏状态，不暴露凭据或原始错误。

## 来源接入

已有研究目录共 213 个入口，其中 153 个是新增候选。门户和部门目录可先进入来源导航，只有确认存在有效新闻/公告列表并通过采样的入口才能开启自动采集。省份导航覆盖 31 个大陆省级区域，不能以此宣称每省已经有稳定资讯流。

首批目标为 20–30 个通过验证的来源，优先国内：约 10 个政策/公告栏目、10 个公司新闻栏目，其余选择稳定的专业媒体和国际数据入口。不是在当前 60 个启用入口上直接追加 153 个，也不要求各省硬凑相同数量。

北京、天津、上海、江苏、浙江、安徽、山东、湖北、湖南、广东、海南、四川、陕西优先定位具体栏目。企业覆盖火箭/发动机、卫星制造、星座、测运控、遥感应用和部件。其他区域先提供来源导航，逐步补齐。国外沿用国家或地区、官方机构、企业及专业媒体层级。

每源在两个有间隔的采样点核验条目链接、真实日期、主题相关性、转载率、解析稳定性和获取成本。已知 ESA 404、部分来源 403/空列表及 LL2 429 均须单独处理，不能因本地偶尔成功就标为线上恢复。

来源 URL 和开关继续放在 `config/sources.yaml`；扩展每源运行环境、频率、地区规则及验证状态。`runtime: snapshot` 和 `runtime: legacy` 必须在生成配置、旧 Worker 及 Actions 三端一起校验，保证同一个生产来源只有一个执行者。地区另建 `config/regions.yaml`，公司复用 `config/companies.yaml` 并补别名与有依据的地区字段。

## 免费方案预算

公共 GitHub 仓库的标准 GitHub-hosted runner 可免费运行；使用标准 Ubuntu runner，不使用大型付费 runner。Actions artifacts 和其他存储另有额度，本方案不靠逐轮上传数据 artifact 持久化。平台依据见 [GitHub Actions billing](https://docs.github.com/en/billing/concepts/product-billing/github-actions)。

R2 Standard 当前包含每月 10 GB-month 存储、100 万次 Class A 操作和 1,000 万次 Class B 操作免费额度；这是账户共享的包含额度，不是绝对费用上限。使用现有 Standard 对象桶，不启用 Infrequent Access，不新增付费套餐。依据见 [R2 pricing](https://developers.cloudflare.com/r2/pricing/)。

按上限 3 MiB 和两份快照估算，资讯对象不超过约 6 MiB，另有少量预算状态；每天 4 轮、每轮读取当前对象并覆盖发布，月度为数百次对象操作，加上网页缓存未命中时的读取。来源样本若扩到 60 个、每源每日最多 4 次、每次最多 2 页，上限为 480 次列表请求/日；不包括个别适配器额外请求，必须通过统一 fetch 包装器实测并设总上限。首版每日最多 600 个外部请求、单轮最多 150 个，内部 `control.json` 预留每轮配额；手动补跑也共享当天剩余额度，任务失败不自动返还预留额度。达到上限则暂停低优先级来源，避免自动增加频率。该小对象每天覆盖计数，不积累日志。

Pages Functions 请求仍受 Workers Free 的共享额度约束；边缘缓存不会让函数请求变成零。上线前核对账号现有共享用量；保持当前免费套餐，并记录使用阈值。R2 不提供本计划能承诺的硬性零账单保障，不能把预算通知当作自动停费开关。预计小流量下上述方案远低于包含额度，但应以实际用量确认。依据见 [Workers pricing](https://developers.cloudflare.com/workers/platform/pricing/)。

Pages Functions 已支持对象桶绑定，沿用现有绑定可减少新增服务。依据见 [Pages bindings](https://developers.cloudflare.com/pages/functions/bindings/)。

## 实施顺序

| 阶段 | 工作 | 完成条件 |
| --- | --- | --- |
| 1 来源与数据契约 | 选择试采来源，确定地区/公司分类、日期和窗口规则，定义 JSON schema | 有真实样本；候选入口和可采栏目清楚区分 |
| 2 独立采集与快照 | 新建 TypeScript runner、合并裁剪逻辑、R2 发布和 Actions 工作流 | 本地 fixture 验证；Preview 连续两轮完整通过；生产旧链路尚未切换 |
| 3 页面预览 | 新建快照读取接口，首页/资讯/公司/官方/来源/发射统一接入，移动端验收 | 关闭 D1 访问后仍能浏览；筛选不新增数据库查询；旧链接有恢复入口 |
| 4 切换与观察 | 切换生产页面与来源运行环境，停用旧生产采集 cron | 至少观察 48 小时和 8 个计划调度点，记录延迟、失败及补跑；通过后保留新链路 |
| 5 清理旧依赖 | 更新部署工作流和运行说明，移除前端 D1 依赖与旧后台维护任务 | 不再每日产生旧日志或全量回填；旧库处置另列明确清单 |

生产发布必须验证 `_routes.json` 或等效路由：新浏览入口不能意外落入旧 D1 API。原 CI 的 `deploy-scheduled` 也要同步处理，避免后续 main 合并又把旧 cron 部署回来。切换失败可回退代码和快照读取方式，旧 D1 配额若仍不可用，优先回退至上一版可用快照页面，不能把“回到旧库”作为唯一恢复手段。

既有 D1 历史数据暂不删除，不在改造期间做大规模导出或清库。停止旧定时任务后，旧数据和日志不再持续增长。之前 PR #33/#34 的完整轮转、索引和上游恢复验收仍是旧链路独立事项；本计划不宣称其已恢复，也不要求新快照方案等待旧库恢复才能试采。

## 验收清单

1. 同一条多省/多公司资讯只存一份；全国政策和地方转载不混淆，无法确认的地区不会被猜测。
2. 30 天之外、未来异常日期和栏目导航链接不进入近期资讯；数量与体积均有上限，显示实际覆盖范围。
3. 单源超时、429、空解析、整轮失败和发布失败有回归用例；失败不覆盖为虚假空站，也不刷新实际成功时间。
4. 当前及前一版对象经过裁剪；重跑幂等，并发调度不会互相覆盖新状态，断网时能展示仍有效的上次结果。
5. 普通浏览、公司/省份/类型筛选和发射页均不读 D1；网页不调用 health 轮询。
6. 桌面及移动端完成来源跳转、组合筛选、空状态、更新延迟、旧链接恢复和体积/加载验证。
7. 首批来源连续两轮采样后才生产启用；切换后完成 48 小时观察，未到期来源跳过而不写无意义日志。
8. Typecheck、lint、相关测试、build、配置一致性、布局检查及 CI 通过；套餐保持 Free，其他子域名与服务不受影响。
